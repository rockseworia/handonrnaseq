# 3. Quantification and functional annotation

This chapter estimates reference-guided transcript abundance with StringTie, creates count matrices with `prepDE.py3`, extracts transcript sequences with gffread, and predicts coding regions with TransDecoder.

## 3.1 Install the tools

Use isolated environments and record exact versions:

```bash
conda create -n rnaseq-quant -c conda-forge -c bioconda stringtie gffread
conda create -n transdecoder -c conda-forge -c bioconda transdecoder
```

The original Chinese notes document a successful analysis with StringTie 2.0.4 after problems with other releases. Treat that as project history, not a universal version rule. Before pinning an old release, check the current StringTie release notes and validate the chosen version on a small sample.

Current StringTie distributions provide a Python 3 count-matrix script named `prepDE.py3`; prefer it over creating a Python 2 environment.

## 3.2 Estimate expression with StringTie

```bash
#!/usr/bin/env bash
set -euo pipefail

sample_file="/path/to/sample.name"
bam_dir="/path/to/aligned"
gtf_file="/path/to/annotation.gtf"
output_dir="/path/to/stringtie"
threads=24

mkdir -p "$output_dir"

while IFS= read -r sample || [[ -n "$sample" ]]; do
    [[ -z "$sample" ]] && continue
    sample_dir="${output_dir}/${sample}"
    mkdir -p "$sample_dir"

    stringtie "${bam_dir}/${sample}.sorted.bam" \
        -G "$gtf_file" \
        -p "$threads" \
        -e \
        -B \
        -o "${sample_dir}/${sample}.stringtie.gtf" \
        -A "${sample_dir}/${sample}.gene_abundance.tsv"
done < "$sample_file"
```

Here, `-e` estimates only transcripts supplied by the reference annotation, while `-B` writes Ballgown-compatible tables. Confirm that the GTF contains valid transcript records and that its sequence identifiers match the BAM header.

Do not remove all `gene` records from an annotation as a default fix. If StringTie rejects a GTF/GFF, validate and normalize the file first, preserve the original, and document any transformation.

## 3.3 Create count matrices

Create a two-column, comma-separated sample list:

```text
sample01,/path/to/stringtie/sample01/sample01.stringtie.gtf
sample02,/path/to/stringtie/sample02/sample02.stringtie.gtf
```

Then run the Python 3 script distributed with StringTie:

```bash
python /path/to/prepDE.py3 \
    -i sample_list.txt \
    -g gene_count_matrix.csv \
    -t transcript_count_matrix.csv
```

Confirm the exact options with `prepDE.py3 --help` for your installed version. Check that matrix columns match the sample sheet and identifiers are unique before differential-expression analysis.

## 3.4 Extract transcript sequences

Use gffread with the same reference FASTA used for alignment:

```bash
gffread annotation.gtf \
    -g genome.fa \
    -w transcripts.fasta
```

## 3.5 Predict coding regions

```bash
conda activate transdecoder
TransDecoder.LongOrfs -t transcripts.fasta
TransDecoder.Predict -t transcripts.fasta
```

Run both commands from the same working directory. The predicted peptide file is typically named `transcripts.fasta.transdecoder.pep`.

## 3.6 Functional annotation

The peptide FASTA can be submitted to [eggNOG-mapper](http://eggnog-mapper.embl.de/) for orthology-based annotation. Save the submitted parameters, database/version, job identifier, and downloaded output. Web-service policies and limits may change; do not upload restricted sequences without checking project requirements.

Tools such as TBtools can help reshape annotation tables, but keep the unmodified eggNOG-mapper output and document every transformation.

## 3.7 Expected outputs

At minimum, retain:

- `gene_count_matrix.csv`;
- `transcript_count_matrix.csv`;
- predicted peptide FASTA;
- functional-annotation table;
- per-sample StringTie GTF and abundance table;
- tool versions, scripts, logs, sample metadata, and reference release information.

Differential-expression testing, normalization, batch effects, biological replicates, and interpretation are downstream steps and are not yet covered by this repository.
