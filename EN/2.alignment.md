# 2. Reference preparation and alignment

This chapter uses HISAT2 for splice-aware alignment and samtools to convert, sort, and index the alignments.

## 2.1 Install the tools

```bash
conda create -n rnaseq-align -c conda-forge -c bioconda hisat2 samtools
conda activate rnaseq-align
hisat2 --version
samtools --version
```

If you must compile HISAT2 from source, follow the project's build instructions and keep the compiler inside the environment when possible:

```bash
conda install -n rnaseq-align -c conda-forge gxx_linux-64 make
conda activate rnaseq-align
git clone https://github.com/DaehwanKimLab/hisat2.git
cd hisat2
export CXX="$CONDA_PREFIX/bin/x86_64-conda-linux-gnu-g++"
make -j 8
```

Avoid copying binaries into `/usr/local/bin` unless you intentionally want a system-wide installation and have administrator approval.

## 2.2 Prepare a reference

Prefer a curated genome FASTA and matching GTF/GFF annotation from the same assembly release. For a non-model organism without a suitable annotation, a gene-prediction workflow such as GeneMark may be needed; licensing and installation details change, so follow the official GeneMark documentation rather than treating these notes as a complete protocol.

Validate that the sequence identifiers in the annotation match the FASTA headers before building an index.

### Extract splice sites and exons

```bash
hisat2_extract_splice_sites.py annotation.gtf > genome.ss
hisat2_extract_exons.py annotation.gtf > genome.exon
```

### Build the HISAT2 index

```bash
mkdir -p reference/hisat2
hisat2-build \
    -p 16 \
    --ss genome.ss \
    --exon genome.exon \
    genome.fa \
    reference/hisat2/genome
```

This produces a set of `.ht2` index files. Building a graph index with splice-site/exon information can require substantially more memory than aligning reads, so check the official HISAT2 manual and your scheduler limits.

## 2.3 Align paired-end reads

This script streams SAM output directly into `samtools sort`, avoiding large intermediate SAM files.

```bash
#!/usr/bin/env bash
set -euo pipefail

sample_file="/path/to/sample.name"
data_dir="/path/to/clean_data"
index_prefix="/path/to/reference/hisat2/genome"
output_dir="/path/to/aligned"
threads=8

mkdir -p "$output_dir"

while IFS= read -r sample || [[ -n "$sample" ]]; do
    [[ -z "$sample" ]] && continue

    hisat2 \
        --dta \
        -p "$threads" \
        -x "$index_prefix" \
        -1 "${data_dir}/${sample}_1.fastq.gz" \
        -2 "${data_dir}/${sample}_2.fastq.gz" \
        2> "${output_dir}/${sample}.hisat2.log" \
    | samtools sort \
        -@ "$threads" \
        -o "${output_dir}/${sample}.sorted.bam" -

    samtools index -@ "$threads" "${output_dir}/${sample}.sorted.bam"
    samtools flagstat -@ "$threads" "${output_dir}/${sample}.sorted.bam" \
        > "${output_dir}/${sample}.flagstat.txt"
done < "$sample_file"
```

`--dta` reports alignments suitable for downstream transcript assemblers such as StringTie.

## 2.4 Check the results

For each sample, inspect:

- the HISAT2 summary in `<sample>.hisat2.log`;
- overall and concordant alignment rates;
- `samtools quickcheck <sample>.sorted.bam`;
- the `samtools flagstat` report;
- BAM and BAI presence and non-zero size.

Low alignment rates can reflect reference/sample mismatch, contamination, read-quality problems, strandedness assumptions, or incompatible sequence identifiers.
